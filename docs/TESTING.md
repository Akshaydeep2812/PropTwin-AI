## Not tested

- Cloud deployment, managed MySQL, and HTTPS.
- A public testnet. All chain tests use a local node.
- Real SMTP delivery. Tests cover the "not configured" path and the reset flow with a stubbed sender.
- A real wallet extension such as MetaMask. The browser tests use a real signing key behind the standard EIP-1193 interface.
- Real property data. All model metrics come from synthetic data.
- Load and concurrency beyond the row locks in the code.
- Independent security review, penetration testing, or a contract audit.
- Accessibility beyond labels, roles and validated chart colors. No screen reader pass was done.

## Running the suites

Paths assume the environment from [Deployment](DEPLOYMENT.md).

### Contract

```powershell
npm test --prefix blockchain
```

### Backend and ML

```powershell
cd backend
python -m pytest                    # fast, on SQLite
```

To use MySQL, which is what production runs and which has caught bugs that SQLite did not:

```powershell
$env:TEST_DATABASE_URL = "mysql+pymysql://proptwin:<password>@localhost:3307/proptwin_test"
python -m pytest
```

The MySQL suite **drops and recreates every table in that database**, so never point it at one you need. `proptwin_test` is created automatically when the Docker volume is first made.

The ML tests train a small real model. The chain tests start their own Hardhat node on port 8546, and are skipped if `blockchain/node_modules` is missing, so check that the summary reports no skips.

### Frontend unit tests

```powershell
npm test --prefix frontend
```

### End to end

Start the whole stack, seed the demo data, and activate a model. Then:

```powershell
cd frontend
npx playwright install chromium     # first time only
$env:DEMO_PASSWORD = "<the value from .env>"
npx playwright test
```

Expect **8 tests**. Without `DEMO_PASSWORD`, two of them skip. The tests create users and properties each run, so use a development database.

## What the end-to-end suite covers

The required workflow: register, log in, create a property, request a valuation, create a twin, run a simulation, register on the chain, retrieve the receipt, verify the hash, and view the history. It also covers:

- Reloading a private page, and restoring a session.
- Detecting a change to a hash-covered field, and naming it.
- Verifier review of documents, with the decision reaching the owner.
- Investor browsing without private fields, comparison, favorites, yield and scenarios.
- Every administration section.
- A two-step wallet transfer, a cancelled request, and a valuation commitment.
- Guest access limits, and phone-width layout.

## Testing rules that earned their place

Each of these comes from a real failure while building this project.

- **Run the backend on MySQL as well as SQLite.** SQLite missed whole-second timestamps, and read-snapshot behavior.
- **Round-trip every migration** (upgrade, check, downgrade, upgrade). Autogenerated rollbacks failed twice on MySQL.
- **Look at the screenshots.** Tests passed while the page showed a blank input as the biggest factor in an estimate.
- **Reload pages in browser tests.** Client-side navigation hid a bug in which reloading a private page showed "not found".
- **Repeat browser tests** (`--repeat-each=3`) to expose intermittent failures. That is how the session rate-limit bug was found.
- **Check the test count.** A file skipped by the runner still gives a green result. The Playwright config now fails if a spec is a OneDrive placeholder.
- **Do not trust a pipeline's exit code.** `npm install | tail` reported success on a failed install.
